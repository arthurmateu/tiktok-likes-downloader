TikTok Likes Archiver

No folder selected

This extension can't reach TikTok's servers yet. Firefox treats a manifest's host permissions as optional, so they have to be granted before any download will work.

Pick the folder you want to archive into. If it's an existing myfaveTT folder, run script.py in it first — that converts what's already there, so nothing gets re-downloaded.

Firefox has no File System Access API, so files are written through the downloads API. That can only write inside your browser's download folder — name a subfolder for it here, and change the download folder itself in about:preferences if you want the archive somewhere else.

Optional, and re-runnable. Lets Firefox see what's already on disk, read archive.json back, and play files in the Library — none of which it can do from a download folder alone.

How it works

				
    
					
  1. Pick any folder. Everything is written straight into it — see below.
    2. 
					
  2. 
						Press Sync likes. A TikTok tab opens on your profile in the background and pages
						through the Liked tab from there — carry on browsing, it doesn't need to be in front. It
						may borrow the foreground for a second or two to open the Liked tab, then gives it back.
					
    3. 
					
  3. 
						The first request is always TikTok's own, signed by its own code; the rest are that same
						request replayed with the next cursor. If TikTok refuses the replay the log says so and the
						run falls back to scrolling the tab, which does need it visible — slower, but there is
						nothing in it for a signing change to break.
					
    4. 
					
  4. 
						Media downloads run at the same time as the list is read, because TikTok's media URLs are
						signed and expire.
					
    5. 
				


				
Where files go

				
<your folder>/
  videos/<videoId>.mp4          one file per video
  images/<postId>.jpg           a single-image post
  images/<postId>_01.jpg        a gallery, numbered in order
  archive.json                  every liked item, downloaded or not
  viewer.html                   this Library, as a file you can double-click


				
viewer.html

				

					Rewritten after every sync, and by Write viewer.html above. It is one
					self-contained file — the metadata is baked in and the media loads from
					videos/ and images/ beside it — so the folder browses
					itself with no extension involved, and keeps working if you copy it to another
					machine or a drive.
				

				

					On Chromium it can also talk back to this page: turn on Allow access to file
					URLs on the extension's card in chrome://extensions and it reads
					current metadata instead of the snapshot, and can start a sync. Firefox doesn't
					run extensions on local files at all, so there it stays a snapshot and says so.
				

				

					Converting an existing myfaveTT folder — or an older version of this one, which used
					data/Likes/ — is a one-off: drop script.py into it and run it.
					It moves the media into place and writes archive.json from myfaveTT's
					databases, so nothing is downloaded twice.
				


				
On Firefox

				

					Firefox has no File System Access API, so this build writes through the downloads API
					instead. Three things follow from that:
				

				
    
					
  • 
						The archive root has to sit inside your browser's download folder. Move the download
						folder in about:preferences to move the archive.
					
    • 
					
  • 
						Every file shows up in the download panel, and the list of what's already saved comes
						from your download history. Clearing that history doesn't lose anything — the next
						sync just re-downloads over the top of the files that are already there.
					
    • 
					
  • 
						Firefox can't read a folder it wasn't handed, so Scan an existing folder… is
						what makes the Library play back off disk and what imports a myfaveTT archive.
					
    • 
				


				
Limits

				
    
					
  • No download cap and no paid tiers.
    • 
					
  • 
						Items that TikTok no longer serves (deleted, or the author went private) cannot be
						recovered — they never appear in the list responses.
					
    • 
					
  • 
						If a media URL expires mid-run you'll see failures. Run Sync likes again; only the
						missing files are retried.
